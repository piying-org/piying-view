## Basic Record Usage

`v.record(KeySchema, ValueSchema)` defines an object with string keys and values of a given type. Piying-View maps `record` to a special Group whose keys are added by the user:

<SchemaPreview definition="src/angular/components/definition/record-basic.definition.ts">
  <SchemaDemoComponent slot="preview" client:only="angular" name="record-basic" />
</SchemaPreview>

Make sure record has a container component in `fieldGlobalConfig.types`:

```typescript
options = {
  fieldGlobalConfig: {
    types: {
      record: { type: PiyingViewGroup }, // the Group container handles dynamic keys
    },
  },
};
```

## GroupKeySchema / GroupValueSchema

`FieldFormConfig` provides `groupKeySchema` and `groupValueSchema` to constrain the key and value types of a record:

<SchemaPreview definition="src/angular/components/definition/record-group-key-value.definition.ts">
  <SchemaDemoComponent slot="preview" client:only="angular" name="record-group-key-value" />
</SchemaPreview>

> **Note**: `groupKeySchema` and `groupValueSchema` constrain the dynamically added key/value pairs rather than replacing the record schema.

## Record Validation Behaviour

Validation of record fields follows the standard Group rules:

<SchemaPreview definition="src/angular/components/definition/record-validation.definition.ts">
  <SchemaDemoComponent slot="preview" client:only="angular" name="record-validation" />
</SchemaPreview>

When a value inside the record fails validation, the child field of that key is marked as an error, but the other keys are unaffected.

This page explains how to define and use components in Piying-View: creating several components, non-form controls, property operations, output events, context and more.

## Component Types

| Type       | Description                            |
| -------- | ------------------------------------ |
| Plain component | A component that does not implement ControlValueAccessor |
| Control         | A form control implementing ControlValueAccessor |
| Plain group     | A container component that can hold children |
| Logic group     | Logical combinations of intersect (and) / union (or) |

## Creating Multiple Components

A basic object component is provided out of the box to display its children; you can also customise the presentation or add wrappers.

<SchemaPreview definition="src/angular/components/definition/component-use.definition.ts">
  <SchemaDemoComponent slot="preview" client:only="angular" name="component-use" />
</SchemaPreview>

- **Basic object component**: `v.object({ k1: v.string(), k2: v.number() })` displays its children by default
- **Custom presentation**: switch to a fieldset layout with `setComponent('fieldset')`
- **Adding a wrapper**: add a label with `actions.wrappers.set(['label'])`, add validation with `v.minValue(10)`

## Non-Form Control Components

By default Valibot's strong typing makes every input a form control. To declare a non-form control, use `NFCSchema` (`v.optional(v.void())`); after using it you must specify the component manually with `setComponent`:

## Property Operations and Output Events

Set input properties with `actions.inputs` and listen to output events with `outputChange`:

<SchemaPreview definition="src/angular/components/definition/action.definition.ts">
  <SchemaDemoComponent slot="preview" client:only="angular" name="action" />
</SchemaPreview>

- **Static properties**: `actions.inputs.set({ input1: 1 })` sets input values directly
- **Dynamic updates**: `actions.inputs.patchAsync({ input1: async (field) => 1 })` supports Promise/Observable/Signal
- **Output events**: `outputChange` listens to several outputs of several components at once and lets you react to the combination

## Tagless Components (Angular selectorless)

By default every field component is rendered with an extra host tag (e.g. `<app-input>`). Any field component — plain component, control or form component — can become a **selectorless component** by adding the following three markers: it only projects its content and **produces no host tag**:

1. Add the static marker `static __version = 2` to the class (the library uses it to detect V2 components)
2. Declare `templateRef = viewChild.required('templateRef')` in the class
3. Wrap the whole UI in the template with `<ng-template #templateRef>`

```typescript
import { Component, viewChild } from '@angular/core';

@Component({
  selector: 'app-my-component',
  standalone: true,
  templateUrl: './my-component.component.html',
})
export class MyComponent {
  static __version = 2;
  templateRef = viewChild.required('templateRef');
}
```

```html
<!-- my-component.component.html -->
<ng-template #templateRef>
  <span>Any content; no host tag is rendered around it</span>
</ng-template>
```

> ⚠️ **Note**: selectorless (V2) components **do not bind `actions.attributes` / `actions.events` automatically**. When needed, read them from the template context and apply them with the built-in `AttributesDirective` (`[attributes]`) and `EventsDirective` (`[events]`):

```html
<ng-template #templateRef let-attr="attributes" let-ev="events">
  <div [attributes]="attr()" [events]="ev()">
    <!-- component content -->
  </div>
</ng-template>
```

## Component Type Overview

Piying-View splits reusable units into **four** single-responsibility component types (the same taxonomy used in [Core Concepts](en/getting-started/core-concept/) and [Using Components](en/scenarios/component-use/)):

| Type | Bound to a form control | Can contain children | Typical examples |
| ---- | ----------------------- | -------------------- | ---------------- |
| Plain component | ❌ | ❌ | Avatar, help text, a "send code" button |
| Control | ✅ | ❌ | Input, select, checkbox |
| Wrapper | ❌ | ✅ (wraps a single field) | Label, error message, card |
| Group | ✅ | ✅ | `object` / `array` / `record` containers |

### Plain Components

- They should be atomic components with few external dependencies
- They may use services to fetch external data
- **They have no type mapping**: you must specify `setComponent` (string reference or component class)
- Components relying on `ng-content` / `slot` projection need to be redesigned

### Controls

- A plain component adapted to `ControlValueAccessor` (CVA)
- Supports form control input/output, validation and data transformation
- **Automatic type mapping** — primitive types such as string and number map to registered controls through the `fieldGlobalConfig.types` defaults

### Wrappers

- Decorative components placed around another field to add a label, an error message, a prefix/suffix, and so on
- A field can be wrapped by several wrappers, applied from the outside in
- Declared with `actions.wrappers.set` / `patch`; see [Wrappers](en/api/wrappers/)

### Groups

- Handle schema types that have children (`v.object()` / `v.array()` / `v.record()`, ...)
- Fully customisable layout (cards, tabs, accordions, ...)
- In Angular, extend `PiyingViewGroupBase` to build one quickly

#### The CVA / CVAA Mechanism

| Name | Description |
|------|------|
| `CVA` (ControlValueAccessor) | Exported and registered automatically; you just export it with the fixed code |
| `CVAA` (ControlValueAccessorAdapter) | Registers the component and binds value and events to it |

> CVA comes from Angular; every framework implements it differently but the idea is the same. Interface definition:
> ```typescript
> interface ControlValueAccessor {
>   writeValue(obj: any): void;
>   registerOnChange(fn: any): void;
>   registerOnTouched(fn: any): void;
>   setDisabledState?(isDisabled: boolean): void;
> }
> ```

## setComponent — Setting the Component Type

`setComponent` chooses the component used to render a field. Two usages are supported:

### String Reference (recommended)

Reference a registered component by its key in `fieldGlobalConfig.types`:

```typescript
import * as v from 'valibot';
import { setComponent } from '@piying/view-angular-core';

const schema = v.object({
  name: v.pipe(
    v.string(),
    setComponent('my-input'), // references fieldGlobalConfig.types['my-input']
  ),
});
```

The matching options configuration:

```typescript
options = {
  fieldGlobalConfig: {
    types: {
      'my-input': { type: MyInputComponent },
    },
  },
};
```

### Passing a Component Class

Pass the component constructor directly:

```typescript
import { setComponent } from '@piying/view-angular-core';

const schema = v.object({
  name: v.pipe(
    v.string(),
    setComponent(MyInputComponent), // reference the component directly
  ),
});
```

> **Tip**: string references are more flexible and keep the type mapping centrally managed in `fieldGlobalConfig`.

### Complete FieldFormConfig Fields

The fields fall into two groups: **manually configured** and **automatically assigned**:

#### Manual Configuration

| Field             | Type                                          | Description                      |
| ----------------- | --------------------------------------------- | ------------------------------- |
| `disabled`        | `boolean`                                     | Disable this field                |
| `disabledValue`   | `'reserve' \| 'delete'`                       | Value strategy while disabled      |
| `emptyValue`      | `any`                                         | Initial empty value for group/array |
| `deletionMode`    | `'shrink' \| 'mark'`                          | Array deletion mode                |
| `validators`      | `ValidatorFn[]`                               | Custom synchronous validators      |
| `asyncValidators` | `AsyncValidatorFn[]`                          | Custom asynchronous validators     |
| `updateOn`        | `'change' \| 'blur' \| 'submit'`              | When updates are applied           |
| `transformer`     | `{ toView?, toModel? }`                       | Value transformer                  |

#### Automatic Assignment (inferred from the Valibot schema)

These fields are computed by `CoreSchemaHandle` from the Valibot schema type and usually need no manual configuration:

| Field             | Source                                          | Description                           |
| ----------------- | --------------------------------------------- | ----------------------------------- |
| `required`        | `!this.undefinedable && !this.nullable`          | true when neither optional nor nullable |
| `undefinedable`   | `v.optional()`                                   | true automatically with `v.optional()` |
| `nullable`        | `v.nullable()`                                   | true automatically with `v.nullable()` |
| `defaultValue`    | Valibot optional default / null → `null`         | Without an explicit default: nullable→null, otherwise undefined |
| `groupMode`       | Inferred from the schema type                    | tuple→'default', loose_tuple→'loose', strict_tuple→'strict', object→'default', array/reset→'reset' |

> **Tip**: manual values override the inferred ones, which is useful for special cases.

## Full Example

```typescript
import { Component, signal } from '@angular/core';
import { PiyingView } from '@piying/view-angular';
import * as v from 'valibot';
import { formConfig, setComponent } from '@piying/view-angular-core';

@Component({
  standalone: true,
  imports: [PiyingView],
  templateUrl: './basic-field-example.component.html',
})
export class BasicFieldExampleComponent {
  model = signal({
    name: 'John Doe',
    age: 25,
    email: '',
    bio: '',
  });

  options = {
    fieldGlobalConfig: {
      types: {
        string: { type: TextInputComponent },
        number: { type: NumberInputComponent },
      },
    },
  };

  schema = v.object({
    name: v.pipe(v.string(), formConfig({ required: true, defaultValue: 'Anonymous' })),
    age: v.pipe(v.number(), formConfig({ defaultValue: 18 })),
    email: v.optional(v.string()), // optional → required = false
    bio: v.pipe(
      v.nullable(v.string()), // nullable → nullable = true
      formConfig({ disabled: true }), // read-only field
    ),
  });
}
```

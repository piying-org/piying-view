## Validator Function Signature

```typescript
interface ValidatorFn {
  (control: AbstractControl):
    | ValidationErrorsLegacy // old format: { [key: string]: any }
    | ValidationErrors2[] // new format: structured error array
    | null
    | undefined;
}

// ValidationErrors2 is a union type including:
type ValidationErrors2 =
  | { kind: 'valibot'; metadata: v.BaseIssue<unknown>[] } // Valibot validation failure
  | { kind: 'error'; metadata: Error } // captured exception
  | { kind: string; metadata?: any; message?: string }; // custom error
```

**Return values:**

- Return `null` / `undefined`: validation passed
- Return `{ [errorKey]: errorValue }`: old-format error (backward compatible)
- Return `[{ kind, metadata, message? }]`: new-format error (recommended)

## Combining Custom Validators with Valibot Validation

Piying-View supports both built-in Valibot validation and custom validators; they **run in parallel**:

  <SchemaDemoComponent slot="preview" client:only="angular" name="validation-combined" />

Errors from Valibot validation and custom validators are merged into `control.errors`:

```typescript
// input "test@test.test"
control.errors = [
  { kind: 'valibot', metadata: [...] },           // Valibot validation failed
  { kind: 'testDomain', message: '...' },        // custom validator failed
];
```

## Handling Validation Errors

Piying-View's FieldControl exposes a standard interface for validation state:

| Property              | Type                               | Description                       |
| -------------------- | ----------------------------------- | -------------------------------- |
| `control.errors`     | `ValidationErrors2[] \| null`       | All current errors (Valibot + custom) |
| `control.valid`      | `boolean`                           | Whether every validation passed    |
| `control.status$$()` | `'VALID' \| 'INVALID' \| 'PENDING'` | Validation status (incl. async pending) |
| `control.dirty`      | `boolean`                           | Whether the value has changed      |
| `control.touched`    | `boolean`                           | Whether it has been focused        |
| `control.pristine`   | `boolean`                           | Whether it is unchanged            |

**Accessing new-format errors:**

```typescript
if (control.errors) {
  for (const error of control.errors) {
    if (error.kind === 'usernameTaken') {
      console.log('username already taken:', error.metadata?.value);
    } else if (error.kind === 'valibot') {
      // Valibot validation failure
      const issues = error.metadata;
    }
  }
}
```

## Comparing the Two Validation Styles

Piying-View supports two validation styles that **run in parallel**:

| Validation style | Description                    | Characteristics                    |
| ------------ | ------------------------------- | ---------------------------------- |
| Valibot validation | Runs during the Valibot parsing phase | Can only validate itself, no access to context values |
| Control-level validation | Registered via `formConfig.validators`, runs independently | Can access parents and other field values |

```ts
// Valibot built-in validation
v.pipe(v.string(), v.minLength(5));

// custom validation
v.pipe(
  v.string(),
  v.check((value) => value === 'k2-value', 'should input k2-value'),
);
```

**Merging errors**: the two styles run completely independently — one failing never skips the other. `control.errors` lists the custom validator errors first; if Valibot validation fails, a `{ kind: 'valibot', metadata: issues }` error is appended.

## Internationalising Valibot Validation

Valibot ships ready-made i18n support; load the locale matching the browser language:

```ts
import '@valibot/i18n/zh-CN';
import { setGlobalConfig } from 'valibot';

const browserLanguage = navigator.language;
if (browserLanguage.startsWith('zh')) {
  setGlobalConfig({ lang: 'zh-CN' });
}
```

> Internationalisation of control-level validation must be implemented yourself in the wrappers and components that display error messages.

## Step 2: Register Component Types

Inside the Angular component, map type names to components through `fieldGlobalConfig.types`:

```typescript
import { Component, signal } from '@angular/core';
import { FormsModule, NG_VALUE_ACCESSOR } from '@angular/forms';
import { PiyingView, BaseControl, PiyingViewGroup } from '@piying/view-angular';
import * as v from 'valibot';

// === text input (shared by string / number) ===
import { forwardRef } from '@angular/core';
@Component({
  selector: 'app-input',
  standalone: true,
  imports: [FormsModule],
  providers: [
    {
      provide: NG_VALUE_ACCESSOR,
      useExisting: forwardRef(() => InputComponent),
      multi: true,
    },
  ],
  template: `<input [(ngModel)]="value$" [disabled]="disabled$()" />`,
})
class InputComponent extends BaseControl {}

// === example component (registers and renders the form) ===
@Component({
  selector: 'app-example',
  standalone: true,
  imports: [PiyingView],
  template: `<piying-view [schema]="schema" [(model)]="model" [options]="options"></piying-view>`,
})
export class ExampleComponent {
  // two-way bound model data
  model = signal({ name: '', age: 0 });

  // Options configuration
  options = {
    fieldGlobalConfig: {
      types: {
        string: { type: InputComponent },
        number: { type: InputComponent },
        object: { type: PiyingViewGroup },
      },
    },
  };

  // Schema
  schema = v.object({
    name: v.pipe(v.string(), v.minLength(2, 'Name must be at least 2 characters')),
    age: v.pipe(v.number(), v.minValue(18, 'You must be at least 18 years old')),
    email: v.optional(v.string()),
  });
}
```

### Using It in the Template

`<piying-view>` takes three properties:

| Property    | Description                          |
| ----------- | ------------------------------------ |
| `schema`    | Valibot schema defining fields and validation rules |
| `[(model)]` | Two-way binding that syncs the form data |
| `options`   | Options configuration (fieldGlobalConfig, ...) |

### Writing a Field Component

These are simply **custom Angular form controls**. You only need to register `NG_VALUE_ACCESSOR` to get two-way binding. To keep the code short, Piying-View provides the `BaseControl` base class, which already implements `ControlValueAccessor`.

The full implementation of `InputComponent` from the example above:

```typescript
// input.component.ts
import { Component, forwardRef } from '@angular/core';
import { FormsModule, NG_VALUE_ACCESSOR } from '@angular/forms';
import { BaseControl } from '@piying/view-angular';

@Component({
  selector: 'app-input',
  standalone: true,
  imports: [FormsModule],
  providers: [
    {
      provide: NG_VALUE_ACCESSOR,
      useExisting: forwardRef(() => InputComponent),
      multi: true,
    },
  ],
  template: `<input [(ngModel)]="value$" [disabled]="disabled$()" />`,
})
export class InputComponent extends BaseControl {}
```

Key points:

- **Register `NG_VALUE_ACCESSOR`** — the standard Angular two-way binding mechanism Piying-View uses to talk to your component
- **Extend `BaseControl`** — it removes the `ControlValueAccessor` boilerplate and gives you the `value$` (current value) and `disabled$` (disabled state) signals
- `[(ngModel)]="value$"` — two-way binding; Piying-View sets the value and listens to changes through `NG_VALUE_ACCESSOR`
- `disabled$()` — reads the disabled state

> **Tip**: for `setComponent`, `formConfig` and the rest of the Actions see [Basic Field Definition](en/scenarios/basic-field/); [API: setComponent](en/api/setcomponent/) compares string references with passing component classes directly.

Run `ng serve`, open the page in your browser and you get a form with the name, age and email fields. As you type, the `model` signal updates in sync.

## Recap

| Step          | Description                                                |
| ------------ | --------------------------------------------------------- |
| Define schema | Use Valibot `v.object()` / `v.pipe()` for fields and rules  |
| Register types | `fieldGlobalConfig.types` maps type names to components    |
| Pass options  | The three core arguments: `schema` + `model` + `options`    |
| Two-way binding | `[(model)]="model"` keeps the data in sync               |
